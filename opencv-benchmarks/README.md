# 30-секундный замер OpenCV

Здесь собраны скрипты, замеры и графики времени обработки кадров.

## Что измеряется

Каждый кадр Full HD (1920×1080) проходит три операции OpenCV: BGR в оттенки серого, Gaussian Blur 5×5 и Canny. Замер включает только обработку уже захваченного кадра; чтение с камеры, отображение, межпоточные буферы и распознавание нейросетью сюда не входят.

В сохранённом образце «хорошо» обработан синтетический кадр в облачной среде на AMD EPYC 9V74 с четырьмя потоками OpenCV. Получено 4151 кадр за 30 секунд: среднее 7,23 мс, медиана 7,02 мс, P90 7,90 мс, пропускная способность 138,36 кадра/с. Это пример производительности данного облачного замера, не результат на ноутбуке.

Массивы «плохо» и «очень плохо» — воспроизводимая симуляция задержек с фиксированными начальными значениями генератора. Они иллюстрируют обработку около 40 мс и 90 мс на кадр, а не измерения на отдельном оборудовании.

## Запуск

```bash
python3 -m pip install -r requirements.txt
python3 opencv_30s_benchmark.py
python3 opencv_scenarios.py
python3 opencv_3d_scenarios.py
```

Первый скрипт выполнит новый 30-секундный замер на текущем компьютере и перезапишет `opencv_30s_results.csv` и `opencv_30s_benchmark.png`. Второй создаст сравнительные данные и графики; третий построит интерактивные HTML и PNG для трёх сценариев. Все результаты сохраняются рядом со скриптами.

## Как читать графики

В обычных графиках X — прошедшее время теста, Y — миллисекунды на кадр. Линия 33,3 мс показывает временной бюджет для 30 FPS.

В 3D-графиках X — время теста, Y — время обработки кадра, сгруппированное в интервалы по 5 мс, Z — доля кадров в таком интервале за каждую секунду. Отдельные плоскости показывают порог 30 FPS и рассчитанные по массиву P90 и P98. Область при больших задержках за P90 содержит самые медленные 10% кадров, за P98 — худшие 2%.

Интерактивные HTML-файлы автономные: их можно открыть локально и вращать график без подключения к интернету.
